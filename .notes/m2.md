```

multiboot magic : 0x2BADB002 (OK)
multiboot info  : 0x9500
[M0] boot foundation: VGA + serial online
nyx: M0 OK

EXCEPTION 3 (Breakpoint) eip=0x1318F2 err=0x0
[M2] returned from int3 (iret works)

```

The `EXCEPTION 3 (Breakpoint)` line proves the `int $3` self-test fired through
the IDT into `isrHandler`, and `[M2] returned from int3 (iret works)` proves the
common stub restored state and `iret`'d cleanly. No QEMU reset loop.

## Files
- `src/gdt.zig` — flat 3-entry GDT (null / code 0x9A / data 0x92, gran 0xC),
  `lgdt` + segment reload via `mov`s and `ljmp $0x08,$1f`.
- `src/idt.zig` — 256-entry IDT, `setGate(n, handler, type_attr)`, `load()`.
- `src/interrupts.zig` — `Frame` extern struct, 32 ISR stubs + common stub,
  `isrHandler`, `init()`.
- `src/main.zig` — wired `gdt.init()` / `interrupts.init()` / `int $3` self-test.

## Stub approach
One file-scope `comptime { asm(...); }` AT&T block. Two `.macro`s (ISR_NOERR /
ISR_ERR) generate `isr0..isr31` exporting global symbols; error-code vectors
(8,10,11,12,13,14,17) skip the dummy push so the Frame layout is uniform. Each
stub does `cli`, pushes dummy-0 (if needed), pushes the vector, `jmp isr_common`.
`isr_common`: `pusha`, `push %ds`, load 0x10 into ds/es/fs/gs, `push %esp`
(Frame ptr), `call isrHandler`, `add $4`, restore segs, `popa`, `add $8` (drop
int_no+err_code), `iret`. Stubs declared in Zig as `extern fn isrN() void` and
referenced by `@intFromPtr` in `init()`.

## Debugging notes
- No triple-fault encountered; the frame push order matched on the first boot.
- Only build hiccup: Zig 0.15.2 rejected the legacy `: "clobbers"` asm syntax in
  gdt.zig/idt.zig. Fixed with `zig fmt` auto-upgrade to the new
  `: .{ .ax = true, .memory = true }` clobber form.
