# M4 — PS/2 keyboard + serial console input + line reader

## What was built
- `src/keyboard.zig` — PS/2 scancode set 1 driver. US-QWERTY make/break tables
  (unshifted + shifted), shift (0x2A/0x36 make, 0xAA/0xB6 break) toggles the
  shifted table, 0xE0-prefixed extended sequences skip the following byte.
  `handleIrq()` reads port 0x60, maps make codes to ASCII, pushes non-zero bytes
  into the shared input ring. Enter→'\n', backspace→0x08.
- `src/input.zig` — 256-byte head/tail ring buffer fed by BOTH the keyboard IRQ
  (`push`) and the serial poller, drained by the shell (`pop`).
  - `getchar()` blocks: drains the ring, then polls `serial.getcNonblock()`
    (treating '\r' as '\n'), then `hlt`s until the next IRQ (~100x/s timer wake).
  - `readLine(dst)` echoes each char, handles backspace (erases + emits "\b \b"),
    stops on '\n', never overflows dst.
- `src/interrupts.zig` — `irqHandler` now dispatches irq1 → `keyboard.handleIrq()`
  (EOI still always sent).
- `src/main.zig` — M4 self-test: `pic.clearMask(1)`, prompt, `readLine`, echo back.

## Ring-buffer + serial-poll approach
Single core, so a plain head/tail ring is safe: the IRQ producer writes the slot
*before* advancing `head`; the reader only touches `tail`. No locking needed.
The automated test drives input over COM1 (not a real PS/2 keyboard), so
`getchar` polls the serial line in addition to the keyboard ring — that headless
path is what the test exercises.
